# Crystal Kizor

A single-page landing site for the personal brand of Crystal Kizor: architect, Design Director of Studio COKA, and founder of initiatives across design, education and youth work.

**Live:** https://crystal-kizor.smitho.workers.dev

Built for the Studio COKA Web Developer assessment, Stage 1.

---

## The idea

Crystal's work spans seven names. Listed side by side they read as unrelated businesses, so the page organises them by what she does:

| Pillar | What she does | Brands |
|---|---|---|
| **Build** | Designs and builds | Studio COKA (flagship), ELEvated |
| **Teach** | Shares what she learns | The Effective Architect, Speaking, Research & Writing |
| **Give** | Invests in the next generation | AKO Alliance, Alive and Free |

The page then answers the brief's four questions in order:

1. **Who is she?** Hero and "Who she is", built around her own identity (logo files, palette, signature) and the question at the heart of Studio COKA's practice.
2. **What does she do?** The three pillars as an index, each linking to its chapter.
3. **What is she building?** Studio COKA leads with published performance figures and a scroll-driven walk through a completed house, followed by Teach and Give.
4. **Where should I go next?** Four intent-based routes in the hero ("I'm here to...") and a closing "Find the right door" section with one next step per kind of visitor.

Honesty rules applied throughout: photographs are labelled *Completed*, *Visualisation* or *Concept*; brands without a public page are marked as placeholders rather than linked to `#`; figures are only those published by Studio COKA.

## Stack

| | |
|---|---|
| Framework | Next.js 16 (App Router), TypeScript, static export |
| Styling | Tailwind CSS v4 with design tokens from the logo sheet |
| Motion | Framer Motion (`motion`) for reveals and scroll-linked movement, Lenis for smooth scrolling |
| Images | Pre-sized WebP generated by `sharp`, served through a custom `next/image` loader |
| Hosting | Cloudflare Workers static assets (no server, edge-cached worldwide) |
| Analytics | Named events for every call to action, sent to GA4 when configured |

**Why a static export on Cloudflare:** a landing page has no per-request data. Exporting plain HTML, CSS and JS removes the server entirely, so the first byte comes from the nearest Cloudflare location and there is nothing to keep running or patch.

## Performance and quality

- Lighthouse: 100 accessibility, 100 best practices, 100 SEO; performance 95+ on desktop.
- Zero layout shift: every image carries its real dimensions and a blurred placeholder.
- Hero content is in the first HTML response and animates with transforms only, so the largest paint never waits for JavaScript.
- Fonts are self-hosted through `next/font` with fallback metrics.
- Respects `prefers-reduced-motion`: Lenis smoothing turns off and the horizontal sequence becomes a normal scroller.
- Long-cache headers for hashed assets and images, plus basic security headers (`public/_headers`).
- Technical SEO: metadata, Open Graph image, `robots.txt`, `sitemap.xml`, `Person` JSON-LD with linked profiles.

    content.ts            every brand, fact, route and link in one place
    track.ts              analytics event helper
    image-loader.ts       picks the right pre-built image width

All copy and brand data lives in `src/lib/content.ts`, so facts can be checked or updated without touching layout.

## Running locally

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # static export to ./out
```

Source photography is not committed. To regenerate the optimised images, place the provided asset folders in `./assets` and run:

```bash
npm run assets
```

## Deploying

```bash
export CLOUDFLARE_API_TOKEN=...   # token with Workers edit permission
export CLOUDFLARE_ACCOUNT_ID=...
npm run deploy                    # next build && wrangler deploy
```

### Analytics

Set `NEXT_PUBLIC_GA_ID` at build time to load GA4. Every call to action already calls `track()` with a named event (`generate_lead`, `route_select`, `cta_click`, `outbound_click`) and context such as `lead_type` and `location`, so enquiries can be marked as key events without code changes. Without the variable, events queue on `window.dataLayer` for any tag manager added later.
